# Performance work

An item closes only when its acceptance check has passed on the current tree.
Historical measurements are investigation snapshots, not gate evidence.

Working rules:

- Compare generated code by instructions executed, then read the assembly.
- A change counts only if checksums still match and the suite stays green.
- Reproduce one benchmark or fixture at a time before changing anything.

## NYR

State on 2026-11-18 12:27 (full run, 110 fixtures, all checksums matching):
NYR geomean 1.46× of C over 109 valid comparisons, 43 at or under 1.2×
(was 1.54× and 39 the same morning); LLVM 1.23×. The
[benchmark dashboard](../learn/measurements.md#benchmark-dashboard) is
regenerated by every full `./make bench` and lists the largest gaps. Wall
times on this host are noisy (C references moved up to 2× between runs);
judge changes by instruction counts.

- [ ] **At most 1.2x of C on every backend.** No valid, comparable benchmark
  above 1.2x on NYR, NYC, or LLVM. Accept: a fresh complete `./make bench`
  report on an idle host with valid checksums, stable measurements, and
  mixed-assembly review for every row above 1.2x (including the expanded corpus).
- [ ] **Reduce >1.2x runtime gaps (measured).** Use fresh stable bench evidence
  and assembly/instruction comparison, checksum-correct fixes only. Largest
  rows by instructions executed relative to C (whole process, 2026-11-18):
  - `radix-tree` (10.7×, was 24.5×): the 20-step bit loop now unrolls
    (descending loops, up to 32 trips) and folds `node * 2 + bit` into one
    `lea`. Remaining: `(x >> k) & 1` still costs a copy because the AND does
    not reuse its dying source's register; C collapses the whole loop.
  - `cd` (8.5×): per-iteration reloads of `px[i]`/`py[i]` (needs load
    hoisting with a no-store proof) and C's vectorized pair loop.
  - `viterbi` (5.9×, was 6.6×): the running max is now a select; `rt_main`
    register pressure still spills the loaded value across the modulo.
  - `stream` (4.3×): the triad is scalar. Vectorizing needs a 4-lane i64
    multiply; AVX2 has none, and the `vpmuludq` emulation needs two scratch
    ymm registers beyond the reserved ymm14/ymm15.
  - `mont64` (3.3×, was 4.8×): fixed-trip limb loops with stores now unroll;
    the remaining limb arrays live in memory (scalar replacement of small
    fixed buffers would keep them in registers).
  - `bitcount` (2.4×, was 3.2×): popcnt now register to register; C
    vectorizes the SWAR form.
  - `bce-matrix` (2.9×), `nussinov` (2.7×),
    `dijkstra` (2.7×), `sssp` (2.2×), `qrsyndrome` (2.2×), `permute` (1.5×,
    was 2.1×), `nqueens` (1.95×), `gcbench` (2.0×): loop home traffic and
    allocation; `permute`'s fixed 10-trip inner loop is not yet unrolled.
  - `towers` (1.30× wall, was 2.5×): shrink-wrapped base case and parameter
    slots used as homes; the remaining cost is five callee-save pushes per
    call.
  - `currying` (sub-ms): every partial application allocates a closure and
    calls through the dynamic closure path.
  Use instruction counts for allocation-heavy rows; their wall time is
  bimodal on this host.

Measurement rule: use focused fixtures while diagnosing; use the complete
benchmark and inspect timed-kernel assembly only after correctness is restored.

## Vectorization

- [ ] **`binary` scalar fallback:** the gate now passes with outer
  vectorization on by default (919 us vs 266 us LLVM, 3.45x, 2026-11-05 full
  run). With `NYTRIX_OUTER_VECTORIZE=0` the scalar loop is still 1.45 ms
  (5.45x). Remaining scalar ideas, about 5% each: branch on the decrementing
  IV's flags instead of `cmp i, d`, and drop the second scalar IV.
- [ ] **FPR/vector residency in `linpack` and `dgemm`:** `spectral`,
  `mandelbrot`, and `page-rank` are done (see
  [measurements](../learn/measurements.md#performance-todo-batch-2026-11-04)).
  `dgemm` is 154 us (LLVM 26 us; 5.97x in the 2026-11-05 targeted run). Three
  of its four invariant broadcasts now stay in registers and are built with
  register-form `vbroadcastsd`. What remains is scalar GPR work in the inner
  loop: `r*M` and `k*M` are recomputed every iteration because LICM refuses to
  hoist address arithmetic (`licm_memory_address_component`), dead address
  temporaries are stored to homes, and base pointers are reloaded. LLVM's loop
  is 13 instructions; ours is about 30. `linpack` (739 us vs 240 us) needs
  vectorization of its row update once rows `r != k` are proven disjoint.
